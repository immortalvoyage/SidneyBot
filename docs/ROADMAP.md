# ImmortalVoyage Platform V1.0 Roadmap

更新日期：2026-08-07

## 目前優先順序

1. 老祖 AI：加速人格、可信回答、記憶、心境、主動需求判斷與成員媒合整合。
2. Discord：完成管理、成員、遊戲資料及老祖互動的正式環境驗證。
3. Apps Script：維持兌換碼與既有資料流程，逐步統一平台 API。
4. Cloudflare：承載 Discord Worker、KV 與安全 API。

## 網站（暫停開發，保留於 V1.0）

- 狀態：依宗主指示暫停，不從 V1.0 移除。
- 原始碼：必須存放於 ImmortalVoyage 的 GitHub 儲存庫，以 Git 保存完整版本歷史。
- 架站方向：使用 Google 資源；預定以 Firebase Hosting 作為靜態／前端託管，必要的 Google Apps Script 或 Google Cloud 服務透過 API 串接。
- 安全：API Key、Token、Secret、Password、Webhook 不得提交至 Git，僅使用 Secrets、環境變數或 PropertiesService。
- 恢復條件：老祖 AI 與核心 Discord 流程達到 V1.0 可用標準後，再建立或移轉網站程式碼儲存庫與部署流程。

## 老祖 AI 近期里程碑

- [x] 公開頻道中 `@老祖` 且提及其他玩家的訊息建立 30 天跨玩家事件記憶；事件參與者後續與老祖聊天時可自然承接，並強制標示為玩家說法而非已查證事實；DM 不跨人共享。
- [ ] 跨玩家事件以 Cloudflare KV 提供 30 天即時索引，並透過簽章 Apps Script Web App 歸檔到 Google Sheets 長期保存；程式已完成，待設定 URL／Secret、部署與線上驗證。

- [x] 固定人格、情緒、慎重模式與事實邊界。
- [x] 萬象錄關係狀態、每日請安與私人對話記憶。
- [x] 自願公開協助資料、明確同意、需求媒合與隨時撤回。
- [x] 一位玩家可刊登多項專長，舊版單一文字欄位保持向下相容。
- [x] 每位玩家只保留一筆公開專長刊登；重複刊登時先顯示目前內容與新內容，玩家確認更新後才取代舊資料。
- [x] 自然聊天可建立專長刊登草稿；玩家回覆「確認」後實際寫入資料庫並回覆可驗證成功訊息。
- [x] 一般玩家可在聊天中查看、修改、刪除自己的公開刊登。
- [x] 聊天中辨識找人需求，依老祖好感度排序並優先介紹前三名已同意公開的成員。
- [x] 補強「誰的專長是…」「不知道有誰擅長…」等自然找人說法的辨識。
- [x] 宗主管理面板可查看所有實際已刊登專長、確認內容並撤下刊登。
- [x] 聊天中辨識換工作、兼職、副業、接案等意圖，主動詢問是否刊登能力資料；已有刊登者會改走更新確認流程。
- [x] 老祖能力缺口建議佇列；語意相近需求自動合併，宗主管理面板可標記已開發或拒絕，拒絕項目進語意黑名單。
- [ ] 門派、主武學、副武學等遊戲角色資料（與現實需求媒合分離）。
- [x] 私人媒合邀請／接受／婉拒／雙方查詢；沒有雙方同意前不得視為媒合成立。
- [ ] 媒合邀請的 Discord 私訊通知與按鈕式回覆。
- [ ] 以實際平台資料回答兌換碼、名冊與遊戲狀態，不得捏造。

## 跨模組下一階段

- Discord：把玩家自己的刊登管理補成按鈕式介面，降低純文字操作門檻。
- Cloudflare：持續以 BOT_MEMORY KV 作為媒合、草稿、能力建議與邀請的唯一可信資料來源，所有寫入都由 Worker 完成。
- AI：逐步把找人、刊登、更新、管理、功能需求分類改為結構化意圖，降低正規表示式誤判。
- Apps Script：後續將兌換碼與遊戲資料透過統一平台 API 提供給老祖查詢，避免 AI 直接猜測。
- GitHub：所有核心流程新增回歸測試，main 維持可部署狀態後再推正式部署。
